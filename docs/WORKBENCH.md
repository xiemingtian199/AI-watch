## 设计依据

- 参考 [Day One 的时间线与日历浏览](https://dayoneapp.com/guides/tips-and-tutorials/journal-views-in-day-one-for-macos/)，把按日期找记录作为主要导航方式。
- 参考 [Exist 的客观数据、手动记录和主观感受结合方式](https://exist.io/)，将状态自评和个人经历放在客观指标旁边，但不把相关变化解释为因果或健康判断。
- 图表使用 Chart.js，图标使用 Lucide，资源随仓库提供，无运行时 CDN 依赖。
- 示例人物“林川”和 14 天记录均为合成内容；照片仅用于示例场景。个人数据和示例使用独立 dataset，上传永远进入 personal。

## 计算口径

- 日期统一为 UTC+08:00，输入时间必须带时区。区间按本地自然日裁剪；恰好午夜结束不产生下一天空记录。
- 步数和活动能量是样本增量之和，不接受累计仪表快照作为同义数据。跨日区间按持续时间比例分摊，不能代表区间内精确的逐时分布。
- 同一累计指标存在多个来源时，选择当天去重后样本数最多的一个来源；同数按来源名排序。来源以 Apple `sourceName` 优先，否则使用 `source`。摘要提示未叠加其他来源，API 的 `aggregation` 返回选中来源。
- 同来源、同起止时间、同值、同单位的累计样本只计一次。不同区间的重叠或不同值的冲突尚未完全对账，因此结果不保证与 Apple 健康 App 一致。
- 活动能量支持 kcal；kJ 除以 4.184 转换。结构化数据须按 README 中的约定提供单位。
- 睡眠只累计 asleep 类别（或数值 1/3/4/5），按区间并集计算，排除 InBed 和 Awake，不重复累加睡眠阶段；按照自然日切分，不是“睡眠归于起床日”。
- 心率展示当天有效样本的中位数、范围和曲线，不据此推断焦虑、压力或诊断。
- 专注只来自明确的 `focus_session` 起止时间/分钟数，重叠区间取并集，不根据时间或心率猜测工作状态。
- 自评是本人填写的 1-5 分，优先采用保存的当日自评，其次采用导入的 mood。没有记录时为 null，不插值、不补零。
- 概览变化与前一个有记录日期比较，明确显示比较日期；上升或下降只是数值方向，不等于更好或更差。
- 总结为本地确定性事实摘要，展示记录数、来源、场景类别和已有指标；计划事件标为计划，未经证实的素材内容不作为已完成事实。

## 存储与兼容

默认目录 `data/private/`，可通过 `AI_WATCH_DATA_DIR` 指定独立目录。SQLite 包含 events、settings、imports、checkins、feedback。

首次初始化会尝试迁移私有目录根层的 JSONL。损坏文件/记录跳过并在个人资料的加载提示中说明，原文件保留。已有媒体目录不会凭空变成新素材记录；需重新通过数据中心导入。迁移只执行一次，后续 JSONL 使用上传同步。

旧 `/import.html` 跳转到 `/#imports`。旧 `generate_cards.py` 和 `transcribe_audio.py` 命令行工具保留，但旧版 HTTP 接口和 `app/data/cards.json` 不再驱动当前页面。

文件摘要用于文件级去重，规范化事件内容用于事件级去重。一个结构化文件的记录先验证再整批入库；失败不留下部分事件或临时上传文件。相同记录修改摘要后会成为新事件，不提供“按外部 ID 覆盖”语义。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/status` | 本地服务状态 |
| GET | `/api/overview?dataset=personal` | 档案、每日统计、来源与迁移提示 |
| GET | `/api/day?dataset=personal&date=YYYY-MM-DD` | 当日汇总、事件、曲线、自评与反馈 |
| GET | `/api/export?dataset=personal&date=YYYY-MM-DD` | 当日 JSON 附件 |
| GET | `/api/imports` | 个人文件同步历史，不返回私有路径 |
| GET | `/api/template` | CSV 模板 |
| GET | `/api/media/<id>` | 素材内容，支持单段 Range |
| POST | `/api/upload` | 文件字节流；`X-Filename`、可选 `X-Start`、`X-Summary` 采用 URL 编码 |
| POST | `/api/profile` | 保存人物档案和目标 |
| POST | `/api/note` | 保存个人经历 |
| POST | `/api/checkin` | 保存指定日期的自评和感受 |
| POST | `/api/feedback` | 保存按日期和观察类型区分的准确性反馈 |

JSON 写接口携带 `dataset`。数据集仅允许 personal/demo。结构化文件限 64 MB，其他上传限 1 GB，普通 JSON 写请求限 2 MB；单条区间最长 366 天。

## 验收记录

```powershell
python -m unittest discover -s tests -p test_*.py -v
npm run check
```

结果：26 项 Python 测试通过（本机已安装 ffprobe，无跳过）；JavaScript 语法检查通过。

覆盖文件/事件去重、无效批次原子性、NaN/Infinity 拒绝、时区与午夜、跨日累计分配、重复来源、kJ 换算、睡眠并集、专注时长、缺失数据、档案/自评/反馈持久化与隔离、计划标记、旧文件迁移、Apple XML/ZIP、JSONL、实际 WAV 时长探测、HTTP 上传、错误文件清理、Host/Origin 与路径边界、离线资源、导出附件和素材 Range。

第一轮测试发现 Apple ZIP 句柄未释放，已改为显式上下文管理，Windows 上复测通过。
最终边界复核补充了数值型睡眠类别（含 CSV 的浮点表示）和无文字备注专注记录的证据断言；26 项测试再次全部通过。长文本摘要与来源标签允许断行。

浏览器验收在独立 `127.0.0.1:4181` 与 `.runtime/ui-test-data` 下进行，没有把测试内容写入用户个人资料：

1. 用文件选择器上传 `tests/fixtures/workbench.csv`，确认新增 6 条记录，日期为 09/10 和 09/11。
2. 当日显示 5,000 步、76 bpm、90 分钟专注，较前日分别增加 2,000、6、30；无睡眠记录显示空值。
3. 编辑人物介绍和 9,000 步目标，保存自评 5 分和当日感受；刷新后仍保留。
4. 个人时间线显示两个日期，步数平均 4,000；切换自评和 7 天范围，确认只有一个有自评的日期。
5. 从时间线返回每日复盘，新增散步经历，查看专注证据，保存“准确”反馈并确认刷新后保留。
6. 上传示例照片，不填写时间时展示错误；补填时间后重试成功，详情弹窗显示实际图片。
7. 检查 1440px 桌面、768px 平板、390px 和 320px 手机布局。320px 下发现日期栏轻微溢出，压缩图标间距后修复；手机可展开人物侧栏，窄屏保留导出操作。
8. 导出改为服务器附件响应，浏览器收到实际下载事件；不再依赖内存 Blob 下载。
9. 六个维度均显示 14 天示例数据，7/14/30/90 天范围可切换；点击 09/11 的曲线数据点返回该日复盘。记录搜索可筛选样本，正式本地页面的示例照片实际加载成功，浏览器控制台无错误。

这些测试证明本地工作流和合成数据计算，不证明真实健康数据的准确性或大规模导入性能。尚未做医学验证、真实录音内容分析、设备持续采集、跨电脑私人数据同步。
